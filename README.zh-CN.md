# car-apps

> [!WARNING]
> **尚未在 iDrive 7 上测试。** 这些应用和工具仅在 iDrive 8 模拟器及实车上进行过测试。行车记录仪也能安装到 iDrive 7：2.3.5 至 2.3.12 曾在一辆 G20 上成功录制、保存和复制片段，但 2.4.0 的新录像流程尚未在 iDrive 7 实车上运行（见下文对应章节）。氛围灯和座椅应用（配合 Comfort 工具），以及 1.1.1 起的 Tailscale（配合其工具）也能安装到 iDrive 7，但尚未在 iDrive 7 实车上运行。其余应用仅支持 iDrive 8；iDrive 7 车辆保留已有版本：车辆数据 1.1.10、加速计时 1.1.8、故障码 1.1.4 和实时调节 1.0.7（在 iDrive 7 上仅确认了能够使用其应用 SDK 构建）。

IterioDev 为搭载 iDrive 7 和 iDrive 8 的 BMW 主机（MGU）开发的应用和工具。这些应用运行在主机自身的应用平台上，与 BMW 原厂应用一样显示在“*所有应用*”中。

所有应用均通过 GPU 渲染器 `mgu-render` 绘制界面。

**车辆数据（Car Data）**共有七页；汽油车不显示 DPF。燃油与进气、行程、变速箱以及分组详情来自 cauliflowermossgrape 的 idrive7-apps（MIT 许可，见包内 `renderer/kit/NOTICE`）；DPF 页面的思路和数据项来自 2bhacker9 的 DPF Monitor（idrive7-apps issue #88）。尚未经实车测试的项目包括：行程页的耗油量（在车辆数据应用打开时，按本车发动机控制单元的数据学习，标定车辆的燃油信号），以及关闭应用界面后是否继续统计行程；变速箱页面（标为实验性，只读，仅支持 ZF 8HP 的 0F25D0 和 0F21E0 型号，其他型号显示“暂不支持”）；DPF 页面（标为实验性，只读，从未在柴油车上运行）。

**实时调节（Live Adjustments）**只有一个页面，仅在点击选项时发送指令。已实车验证：发动机程序切换可用（1.0.1，MHD）。BMW 的调节型阀门任务可在 G80 S58 MHD 上打开和关闭阀门，但车辆开始移动后 DME 会收回控制权（issue #3）。最大冷却和 MHD 自身的阀门控制（1.0.7）尚未经实车测试。

- **发动机程序 1—4**（MHD）：可随时切换，从 1.1.1 起也允许在行驶中切换，因为 MHD 自身就支持通过巡航控制按钮在行驶中切换程序。DME 必须回显确认请求，否则界面会说明未切换的原因。MHD 不报告当前正在使用的程序，因此界面显示的是 DME 已接受的程序，而非读取回来的当前程序。切换时发动机故障灯可能闪烁，这是 MHD 的行为。
- **最大冷却**（MHD）：任意车速均可请求，确认方式同上。只有发动机运转时（超过 500 rpm）才能*开启*；可随时*关闭*，界面保持显示关闭，直到再次开启。
- **排气阀门**：任意车速均可操作。MHD DME 使用 MHD 自身的阀门控制：*打开*／*关闭*会在行驶中保持，直到再次点击其他按钮；*OEM* 会将控制权交回调校程序。没有 MHD 时，使用 BMW 自身的 DME 任务，并按车辆选择调节型阀门（DID 611E，例如 S58）或普通阀门（DID 60FD）；此时打开／关闭约保持 20 秒，或保持到车辆开始移动，随后 DME 重新控制阀门。界面显示期间每 2 秒读取一次阀门位置。没有电子阀门的 DME 会显示 *NONE*（无）。
- 没有 MHD 的 DME 会拒绝程序和冷却请求。首次拒绝后，界面显示 *MHD not found*（未发现 MHD），并将这两项禁用；阀门仍可通过 BMW 的任务控制。

<a id="installing"></a>
## 安装

1. 先按照 [robertnisipeanu/mgu-store](https://github.com/robertnisipeanu/mgu-store) 的 README 安装商店。其更新器、部署工具、GPU 渲染器（`mgu-render`）和网络上行工具（`mgu-uplink`）是这些应用运行的基础。
2. 在商店中，将此仓库添加为 GitHub 来源：`IterioDev/car-apps`，频道选择 **Tags**。
3. 安装应用，或在“*工具*”中安装工具，然后重启一次主机：iDrive 8 的应用会在下次启动时安装。

从 IterioDev 早期的 App Manager 迁移？你的商店中可能有一个名为 `car-apps` 的来源，指向旧的 `index.json` 链接。该链接已经失效：删除此来源，再按上述方法添加 `IterioDev/car-apps`，随后即可更新已安装的应用。

## 快捷控制栏（Overlays，工具 `iteriodev-overlays`，仅 iDrive 8）

> [!NOTE]
> **已实车测试**（G82）：快捷方式的点击和长按保存；位于原厂位置的座椅加热／通风及方向盘加热（0.3.1）；车辆报告 M 设置时，M1 切换到 SPORT，并在退出时返回 ROAD（0.3.2，0.3.3 起仅由 M1／M2 触发）；默认颜色的氛围灯闪烁（0.3.4）。尚未经实车测试：档位分段、换挡提示灯、TRACK、“启动进入 M SPORT”（0.3.3）、其他闪烁颜色、应用的选择器和设置页，以及以下版本的修改：0.3.7 的修复（AUTO 程序下的座椅加热、发现通风功能后才显示、熄火结束 M 设置、M 车型不显示本工具的换挡灯）；0.3.8（HMI 原生快捷图标）；0.3.9（启动 15 秒后显示控制条、实心电话图标）；0.4.0（右舵设置）。

在空调栏上绘制一条 iDrive 8.5 风格的控制条。主机启动或唤醒且 HMI 出现 15 秒后显示，因此不会覆盖启动黑屏或 M 启动动画；之后始终显示，包括倒车摄像头画面上。

- **快捷方式：** *CLIMATE MENU*（空调菜单）左右各两个，使用 HMI 自带图标（媒体、导航、电话、所有应用）。点击打开该位置保存的页面；长按 1 秒，将当前页面保存到此位置，任何 BMW 页面或应用都可保存。也能在本应用中从列表选择。
- **座椅加热／通风：**位于 HMI 的原厂位置并使用其原生图标：通风在各侧温度的左边，加热在右边。点击循环切换档位，顺序为 1→2→3→关闭，或 3→2→1→关闭。开启时图标变红／蓝，下面的三段线显示档位。始终显示车辆实时状态，也会跟随空调菜单中的更改。仅显示本车具有的功能；如果车辆空调单元无法报告是否配备通风，则在通风开启过一次后显示：先通过原厂 HMI 按钮开启一次，或在本应用中设为 ON。某一侧空调运行 AUTO 程序时，对应按钮改为控制自动座椅加热／通风，提供从低到很高的四档，设置方式与 HMI 相同。
- **方向盘加热：**位于控制条最左侧，点击开关。
- **右舵：**在本应用的空调页，将“方向盘”设为“右侧”（默认左侧）：驾驶员座椅按钮移到右侧，副驾驶按钮移到左侧，方向盘按钮移到控制条最右端。
- **氛围灯闪烁：**默认开启，除非在应用中关闭。座椅或方向盘加热开启时，氛围灯变红 5 秒；通风开启时变蓝 5 秒，然后恢复原颜色。无论从控制条、空调菜单还是座椅按钮开启，都会触发。颜色在应用中按原车氛围灯菜单编号选择，默认 3 和 9，分别为 Coral（珊瑚色）和 Azure（蔚蓝色）。适用于配备 12 色氛围灯的车辆（G8x）；原车氛围灯关闭时不执行。
- **M1／M2**（M 车型）：启用 M 设置时，也会切换 M 模式，效果如同 M Mode 按钮，作用于仪表和抬头显示；停用时返回。M1、M2 和停用状态各自对应的模式，可在应用中设置。只有 M1／M2 会触发：使用 M Mode 按钮手动选择的模式会保留。车辆熄火会结束 M 设置，下次按键重新进入。
- **启动进入 M SPORT**（M 车型，默认关闭，需在应用中开启）：启动后等待仪表就绪，仪表会报告自己的视图，而主机比仪表更早唤醒；若仪表仍显示标准视图，则将 M 模式切换到 SPORT。
- **换挡提示灯：**面向没有原厂换挡灯的车辆，在仪表顶部中央、地图上方左右各显示 8 格，从外向内点亮，在换挡点闪烁；也可显示在抬头显示的车速上方。不用于 M 车型，因为它们有自己的换挡灯，所以工具默认在这类车辆上隐藏自己的提示灯；如仍需使用，可在应用中将“M 车型”设为 NO。根据发动机转速，相对于起亮转速和闪烁转速控制亮灯。转速可在应用中设置，或跟随发动机当前限制，冷机时限制较低。需要 [robertnisipeanu/idrive-apps](https://github.com/robertnisipeanu/idrive-apps) 的 **Cluster renderer（`cluster-render`）0.3.6 或更新版本**；未安装时，其余功能仍照常运行。

工具以 root 服务 `iteriodev-overlays.service` 运行，通过辅助程序 `hmictl`，使用 SOME/IP 与 HMI 和车辆通信。需要 **Renderer（`mgu-render`）0.6.10 或更新版本**，以便将控制条作为叠加层绘制。工具会添加配置片段 `mgu-render.service.d/iteriodev-overlays.conf`，在 `overlay_apps` 中列出自身；渲染器下次启动时读取，所以安装后需重启一次主机。部署工具将 `hmictl` 和服务加入主机的崩溃及重启白名单（`crashNames`、`recmgr`），并限制其核心转储，因此两者任意一个崩溃都不会导致主机重启。应用通过 `/run/iteriodev-overlays/ctl.sock` 与工具通信；设置和快捷位置保存在 `/var/opt/iteriodev-overlays/slots.json`。

<a id="comfort-tool-iteriodev-comfort-idrive-7-and-8"></a>
## Comfort（工具 `iteriodev-comfort`，iDrive 7 和 8）

> [!NOTE]
> **已实车测试**（M4，BDC_G05，座椅模块 FAS_G11／BFS_G11）：八个氛围灯模块的自定颜色，以及停车时的按住移动和记忆调用。尚未经实车测试：氛围灯 1.1.1 及之后的界面、让出空间、行驶中移动座椅、iDrive 7、便捷进出和电动方向柱（0.3.0）、使用座椅占用传感器的副驾驶便捷进出及仅电机座椅（0.4.0）、按驾驶模式配色（0.5.0）。

这是氛围灯和座椅应用背后的 root 服务（`iteriodev-comfort.service`）。通过主机自身的诊断网关，使用原车维修任务与车身控制器和座椅模块通信：按模块设置氛围灯 RGB，每次写入有效 254 秒并持续续期；关闭后立即恢复原车颜色；同一区域的不同灯光类型，例如灯带和饰板，会拆分为可分别配色的部分；启用驾驶模式配色时，根据主机报告的驾驶模式选色。它还控制座椅电机及位置计数器，以及电动方向柱，后者通过车身控制器操作。

座椅与原车开关一样可在任意车速移动，但让出空间和便捷进出要求车辆静止。方向柱仅在车辆静止且已标定时移动，并在自身的软限位处停止。便捷进出会读取各前门、点火或发动机状态，以及车辆能够报告时的座椅占用传感器状态：副驾驶座只有有人时才移动，儿童座椅不会触发。电机没有位置传感器的座椅，常见于只有驾驶侧带记忆的车辆的副驾驶座，仅提供按住移动功能。座椅控制优先于车速和发动机数据读取，因此即使车辆缺少其中一项数据，也能立即响应。每次移动最终都会发送停止指令，座椅原厂开关始终优先。应用通过 `/run/iteriodev-comfort/ctl.sock` 与服务通信；区域颜色和座椅记忆保存在 `/var/opt/iteriodev-comfort/data.json`。

<a id="tailscale-tool-iteriodev-tailscale"></a>
## Tailscale（工具 `iteriodev-tailscale`）

通过你的 tailnet 远程访问主机。Tailscale 1.104.4 以 uid 3910 运行服务 `iteriodev-tailscale.service`，使用用户态网络，因为主机内核没有 TUN；通过 `mgu-uplink` 访问互联网，商店会先安装上行工具。连接主机的 Tailscale 地址时，会转到主机 `127.0.0.1` 的同一端口，因此在主机已开启 SSH 时，`ssh root@<its tailnet name>` 可连接它自身的 sshd。

只需登录一次：在主机上打开 **Tailscale** 应用，手机扫码并授权设备，应用随后显示“*已连接*”。不使用应用时，也可通过 root SSH 执行：

```sh
/var/opt/iteriodev-tailscale/current/ts up
```

它会输出同样的 `https://login.tailscale.com/...` 链接。守护进程的控制套接字向主机上的应用开放，应用通过它登录和退出。登录状态保存在 `/var/opt/iteriodev-tailscale/state`，卸载工具时删除。`ts status` 显示 tailnet 状态。

**在 tailnet 中的名称：**默认为主机自身的主机名 `mgu`，除非你修改它。可在应用中使用“*重命名*”，仅允许 a-z、0-9 和 `-`；“*使用 mgu*”恢复默认值。也可通过 SSH 执行 `ts set --hostname=<name>`。名称会在重启和工具更新后保留，`ssh root@<name>` 和屏幕共享地址也会随之改变。在 Tailscale 管理控制台设置的设备名优先于此名称；名称已被占用时会追加后缀，如 `mgu-1`。可以考虑在 Tailscale 管理控制台关闭此设备的密钥过期。

- 仅在主机运行且上行联网时可访问；车辆休眠时，Linux 会挂起。
- 不向 Tailscale 上传日志，使用 `--no-logs-no-support`；主机自身不配置 MagicDNS。
- `tools/iteriodev-tailscale/build.sh` 从 Tailscale 源码重建二进制，使用静态构建、内置 CLI，只包含主机所需功能；`runas/` 将服务从 root 降权到 uid 3910。`test.sh` 在离线状态下检查有无下述 SOCKS5 设置时的守护进程命令行，不在主机上安装或运行。

**供主机应用使用的 SOCKS5 代理（从 1.104.6 起，默认关闭）：**主机上的应用可以通过本地 SOCKS5 代理访问你的 tailnet，例如游戏串流应用连接你的 PC。以 root 身份通过 SSH 开启：

```sh
echo 1055 > /var/opt/iteriodev-tailscale/socks5-port
systemctl restart iteriodev-tailscale
```

开启后，主机上的每个应用都可通过上行访问互联网，而不限于 tailnet：代理也会以 uid 3910 连接非 tailnet 地址，并由 mgu-uplink 路由。

应用使用 `127.0.0.2:1055` 上的代理，端口取自文件。删除文件并重启即可关闭。端口文件与登录状态一样，位于工具版本目录旁，因此更新会保留它。不是有效端口的值会被忽略：必须是 1—65535，且无前导零。代理只监听 `127.0.0.2`。如果端口被其他程序占用，tailscaled 会在不启用代理的情况下启动，并在系统日志中说明。

- tailnet 无法访问此代理：它监听 `127.0.0.2`，而来自 tailnet 的入站连接转到 `127.0.0.1`，与 SSH 一样。
- **没有身份验证**，因此主机上的所有应用和工具，无论 uid 是什么，都可以使用它。这与向所有这些程序开放、权限为 0666 的守护进程控制套接字采用相同的信任模型。你的 tailnet 访问控制决定车辆能够通过代理访问哪些资源。

<a id="screen-share-tool-iteriodev-screencast"></a>
## 屏幕共享（工具 `iteriodev-screencast`）

> [!NOTE]
> **已实车测试**（1.0.6）：画面显示及 HMI 触摸可用。1.0.7 还会把触摸传递给 `mgu-render` 绘制的应用，这部分尚未经实车测试。1.0.8 用同一构建同时支持 ID7 和 ID8，自动检测屏幕原生分辨率，用于画面尺寸和触摸坐标，无需按车辆单独设置；尚未经实车测试。

通过 tailnet，在电脑浏览器中显示主机中控屏。点击和拖动画面会变为屏幕触摸。需要上文的 Tailscale 工具，且已登录；浏览器可使用 Chrome、Edge、Firefox、Safari。iPhone／iPad 需要 iOS 17.1 或更新版本，其上的任意浏览器均可。

- **画面：**主机自带的抓屏程序 `winston-grabber` 使用硬件将屏幕编码为 H.264，以屏幕原生分辨率输出，自动检测，最大宽度 1600 像素，10 fps，约 1 Mbit/s；使用 SIM 上行时，每小时约 450 MB。只有浏览器打开页面时才运行，最后一个浏览器关闭 5 秒后停止。画面落后屏幕约 0.2 秒，另加网络延迟。状态栏显示帧率、码率和帧到达耗时；上行无法承载数据流时，服务器会跳帧，使画面最多落后约 1 秒，避免延迟不断累积。
- **触摸：**点击为轻点，拖动为滑动，发送方式与显示屏自身的触摸相同。GPU 渲染器运行时先发送给它，以便渲染器应用收到触摸。若关闭标签页或连接中断导致手指状态一直按下，会在 2 秒后自动抬起。不包含 HOME／BACK 按键和 iDrive 旋钮。
- **谁可以使用：**仅通过 Tailscale 响应，监听主机的 `127.0.0.1:5880`；**你的 tailnet 中任何可访问此端口的人，都能观看屏幕并点击操作**。如果 tailnet 与他人共享，请通过访问控制限制 5880 端口。行驶中触摸也会传到屏幕，不要在行驶的车辆上使用。

**安装：**在商店中选择“*工具*”→“**Screen share**”→“*安装*”。如果缺少 Tailscale 工具，会先安装它。随后重启一次主机：服务 `iteriodev-screencast.service` 与 BMW 自带抓屏程序一样以用户 `os_7011` 运行，下次启动时开始等待浏览器连接。

**使用：**打开 `http://<head unit's tailnet name or address>:5880/`，例如 `http://mgu:5880/`。画面开始播放后，状态栏显示 *live, 10 fps*（实时，10 fps）；“*Full screen*”（全屏）使画面铺满显示器。

**无法运行时：**通过 root SSH 手动运行，查看消息输出，不使用服务；Ctrl-C 停止程序及抓屏：

```sh
cd /var/opt/iteriodev-screencast/current && XDG_RUNTIME_DIR=/run/wayland SCREENCAST_PORT=5881 node screencast.js
```

然后访问 5881 端口。尺寸、帧率和编码器设置对应 `screencast.js` 顶部的 `SCREENCAST_*` 环境变量。

<a id="drive-recorder-tool-iteriodev-drplay"></a>
## 行车记录仪（Drive Recorder，工具 `iteriodev-drplay`）

> [!NOTE]
> **已实车测试**（2.4.0 配播放器 1.2.3，iDrive 8，配备 360 摄像头的 G82）：全部摄像头的录像、片段保存和观看。尚未经实车测试：复制 2.4.0 片段到 U 盘（播放器 1.2.4）、仅有前后摄像头的车辆，以及 iDrive 7 上的 2.4.0。2.3.5 至 2.3.12 曾通过主机摄像头服务，在一辆 G20 M340i 上成功录制、保存和复制片段。

应用每次启动时都会请求车辆摄像头控制单元进入行车记录模式，可在设置中关闭。录像页的“*保存片段*”会写入此前 20 秒及此后 10 秒，可在“设置”→“*片段长度*”中调整。可选择的摄像头取决于本车配置：全部摄像头、前后、前方或后方。如果摄像头单元不接受行车记录模式，例如已遇到的某些加装后摄像头，界面会显示 *No drive-recorder cameras found*（未找到支持行车记录的摄像头）。

泊车画面打开时，包括部分车辆启动后自动出现的泊车画面，摄像头会被它占用，期间不录像。因此，恢复后立即保存只能写入从恢复录像以来的秒数，至少录制 5 秒后才可保存，并显示“保存片段 · 此前 N 秒”，不一定有完整长度的片段。

播放器运行两个服务：

- `iteriodev-driverec-rx.service`（从 2.4.0 起，以 root 运行）：直接接收摄像头控制单元的视频流，在内存中保留最近几秒，约占 220 MB；点击“*保存片段*”时，按原车行车记录仪的目录和布局写入。它不再使用主机摄像头服务及其开通标志，因此通过 BMW 在线开通（*OTA*）的车辆也能录像。所有摄像头按控制单元发送的原样保存：两组画面交替传输，每组包含两个摄像头；播放器会将其合成一个完整画面。
- `iteriodev-drplay.service`（uid 3912，无互联网访问）：通过 GPU 渲染器播放片段、生成缩略图、锁定、删除、覆盖最早片段，并复制到 U 盘。可复制完整原始片段，也可将单个摄像头导出为附日期、时间和车速的 MP4。*锁定*会将片段移入目录下的 `locked/`。完整的全部摄像头原始片段在 PC 上播放时，会逐帧切换两组摄像头画面；供 PC 观看时，请复制单个摄像头。

**安装：**在商店中选择“**Drive Recorder**”→“*安装*”，播放器会一起安装，然后重启一次主机。如果从 2.3.x 升级，也需在更新后重启一次，因为接收器是新增服务，要到下次启动才运行。

**U 盘（从播放器 1.1.3 起）：**车辆为媒体播放器将 U 盘挂载为只读，使用 udisks，路径为 `/media/<label>`；播放器只能复制到可写的盘。打开应用的“*复制到 U 盘*”页面或正在复制时，播放器的 `usb-rw.sh` 以 root 将 U 盘重新挂载为读写，并在结束 20 秒后恢复只读。其他时候保持只读，因为车辆不会在拔盘前卸载 U 盘。FAT32 和 exFAT 均可使用。较慢的 U 盘可能停在 99% 一段时间：播放器已提交全部片段，正在等待真正写入 U 盘。

<a id="turn-view-tool-iteriodev-turnview-idrive-8-only"></a>
## 转向实景（Turn View，工具 `iteriodev-turnview`，仅 iDrive 8）

> [!NOTE]
> **摄像头和转向卡片已在实车上运行**（M4，360 摄像头，CarPlay 中的 Apple Maps）。BMW Maps、Android Auto 和仅有前后摄像头的车辆尚未经实车测试。Waze 不向车辆发送转向信息。

导航期间，在仪表小组件显示前摄像头画面、转向卡片和路面指引箭头。工具 `iteriodev-turnview.service` 以 root 运行，读取转向信息，来源为 BMW 导航或 CarPlay／Android Auto 的手机导航；通过自带解码器 `mgu-camcluster` 运行前摄像头画面，并通过 Cluster renderer（`cluster-render`，robertnisipeanu/idrive-apps，0.4.1 或更新版本）绘制到仪表小组件。应用显示状态并用于校准指引箭头。

1.2.0（工具 0.3.0）增加“*转弯前弹出*”选项：关闭、500、250、100 或 50 米。设置后，仪表可在接近每个转弯时自动显示转向实景，无需从小组件菜单选择。摄像头还改为较低分辨率的每秒 15 帧，原先是 10 帧，此项为工具 0.3.1 的修改。这两项尚未经实车测试。

**需要前摄像头：**配备 360 摄像头（Surround View）或前后摄像头的车辆。如果摄像头控制单元无法单独提供前摄像头画面，Turn View 会先请求前后视图，再请求全部摄像头。只提供后摄像头、始终不提供前摄像头的控制单元，会使小组件显示 *No front camera*（无前摄像头），不显示其他内容；完全没有摄像头画面则显示 *No camera*（无摄像头）。（1.1.1／工具 0.2.1：1.1.0 曾在部分具有摄像头的车辆上误显示“无前摄像头”。）

**安装：**在商店中选择“**Turn View**”→“*安装*”，工具会一起安装。首次安装要到主机下次启动时生效；随后在仪表小组件菜单中选择“**Cluster renderer**”。每次工具更新后，仪表会停用该小组件，需要重新选择。工具日志位于 `/var/opt/iteriodev-turnview/turnview.log`。

<a id="what-is-in-this-repository"></a>
## 仓库内容

- `apps/<id>/`：每个应用一个目录，包含安装包 `<id>@<version>.tgz`、`app.json` 和 `icon.png`。`app.json` 记录版本、标题、说明、适用主机和依赖。安装包为源码包，含 `mgu-app.json`，与商店自身的发布方式相同：安装时由商店的部署工具使用该主机自身的应用 SDK 在主机上构建，因此一个包可用于 iDrive 7 和 iDrive 8。
- `tools/<id>/`：每个工具一个目录，包含预构建文件和 `component.json`。
- `mgu-repo.json`：供 mgu-store 读取。`apps/` 下每个目录都是应用，工具则在其中列出。应用的构建步骤 `tools/prebuilt.js` 不执行任何操作，因为安装包已经包含在仓库中。

每次发布使用 `x.y.z` 标签。应用需要商店部署工具 0.7.5 或更新版本，商店会先安装它。
